# Security

MarkupMe renders Markdown that may come from people you do not trust: pull requests, comments, uploaded files, API calls. This page states what we defend against, how, and where the limits are. The design decision is [ADR 0003](../architecture/architecture-decision-records/0003-sanitize-by-default.md). To report a problem, see [SECURITY.md](../../SECURITY.md).

## Threat model

| Asset | Threat | Defence |
| ----- | ------ | ------- |
| Viewers of rendered HTML | Script injection (XSS) through raw HTML, attributes, URLs, SVG | Sanitize by default with an allowlist schema; SVG sanitizer for diagrams |
| Viewers | DOM clobbering through `id`/`name` attributes | User ids keep the `user-content-` prefix |
| Viewers | Clickjacking and content sniffing of the preview server | `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff` |
| Viewers | Tracking through referrers from the preview server | `Referrer-Policy: no-referrer` |
| Diagram source | Leaking private diagrams to a third party | Network diagram rendering (Kroki) is off unless a server is configured |
| Pages | Loading code from a CDN | Mermaid and KaTeX are copied next to the output or served locally; a remote URL needs `--mermaid-url` |
| Preview host | Path traversal through the preview server | Paths are resolved and must stay under the served root (403 otherwise) |
| Preview host | Exposure on a network | Binds `127.0.0.1` by default; CORS off by default |
| Preview host | Memory exhaustion through the API | Request bodies over 1 MB get 413 |
| Preview API | Caller disables sanitizing | `sanitize: false` is ignored unless the server was started with `--unsafe` |

Out of scope:

- Trusted output from your own code block handlers and plugins. They run in your process and their HTML is not sanitized (see [trusted slots](#trusted-slots)).
- Running MDX or any embedded code. MarkupMe never executes document content. MDX output is planned and will need its own trust boundary.
- Denial of service through pathological Markdown. Parsing is done by micromark; we have not measured worst-case inputs.
- Content Security Policy for your site. The standalone page uses inline `<script>` and `<style>`, so a strict CSP needs your own hashes or nonces, or `runtime: false` plus an external stylesheet (`cssHref`). We do not ship a CSP.

## HTML pipeline

`renderHtml` in `packages/core/src/render/html.ts` runs these steps in order:

1. **Presentation on a copy.** Alerts, directives, emoji and plugin `render` hooks change a `structuredClone` of the tree. The document is not touched.
2. **mdast to hast.** `remark-rehype` with `allowDangerousHtml` (when HTML is allowed) and an empty clobber prefix. Raw HTML is still an unparsed `raw` node.
3. **Record trusted ids.** Every `id` present now was generated by MarkupMe (headings, footnotes). They go into a set. Raw HTML has not been parsed yet, so no user id can get in.
4. **Code blocks to slots.** Each `<pre><code>` is offered to the code block handlers. When one returns HTML, the block is replaced by an empty `<div id="mm-slot-<nonce>-<n>">` and the HTML is kept aside. The nonce is 6 random bytes from `crypto.getRandomValues`, new for every render, so a document cannot guess a slot id.
5. **Plugin `rehype` hooks** run on the hast tree. Their changes are sanitized in the next step like everything else.
6. **Parse raw HTML, then sanitize.** `rehype-raw` turns raw HTML into elements. `rehype-sanitize` then cleans the whole tree with `markupmeSchema`.
7. **Un-clobber our ids.** The sanitizer prefixes every `id`, `name`, `aria-describedby` and `aria-labelledby` with `user-content-`. MarkupMe removes the prefix only when the unprefixed value is in the trusted set from step 3 (or is a slot id). Ids written by the author keep the prefix.
8. **Links, images and tasks.** `baseUrl` resolution, `target`/`rel` for external links, `loading`/`decoding` on images, heading anchors, an `aria-label` on task checkboxes.
9. **KaTeX** (when math is on) renders math nodes. This runs after sanitizing, so KaTeX's own `style` attributes are kept; KaTeX output is treated as trusted.
10. **Fill slots.** Each slot `<div>` is replaced by its trusted HTML.
11. **Stringify** with `allowDangerousHtml: true`, which only affects the raw slot HTML inserted in step 10.

### The schema

`markupmeSchema` (`packages/core/src/render/schema.ts`) is the `hast-util-sanitize` default schema, which follows GitHub's sanitizer, plus:

- Tags: `nav`, `section`, `figure`, `figcaption`, `mark`, `abbr`, `aside`.
- Attributes on all elements: `role`, `aria-label`, `aria-hidden`, `data-footnotes`, `data-footnote-ref`, `data-footnote-backref`.
- `a`: `target`, `rel`. `img`: `loading`, `decoding`. `abbr`: `title`. `details`: `open`.
- `class` only from an allowlist: `mm-*`, `markdown-alert*`, `language-*`, `contains-task-list`, `task-list-item`, `footnotes`, `sr-only`, `data-footnote-backref`, `math`, `math-inline`, `math-display`. Any other class is removed.

Still blocked: `<script>`, `<style>`, `<iframe>`, `<object>`, `<embed>`, `<form>`, `<input>` (except GFM task checkboxes), all `on*` handlers, `style` attributes, and URLs with schemes outside the default allowlist (so no `javascript:`, `vbscript:`, `data:`).

### What the tests prove

`packages/core/test/core.test.ts`, `describe('security')`, renders each of these with default options and asserts the output has no `<script`, no `on*=` attribute on a tag, no `href="javascript:`, no `<iframe`, no `style=`, no `<form`, no `<style`, and no `id="location"`:

```text
<script>alert(1)</script>
<img src=x onerror="alert(1)">
[x](javascript:alert(1))
<a href="javascript:alert(1)">x</a>
<iframe src="https://evil.example"></iframe>
<div style="background:url(javascript:alert(1))">x</div>
<svg><script>alert(1)</script></svg>
<math><mtext><table><mglyph><style><img src=x onerror=alert(1)>
<form action="https://evil.example"><input name="pw"></form>
<a href="#" id="location">clobber</a>
```

Two more tests check that trusted handler output survives sanitizing and that raw HTML is kept only when `sanitize: false`. The serve API test `renders sanitized HTML with diagrams and stats` sends `sanitize: false` to a server started without `--unsafe` and checks that `<script>` is still removed. End to end, the SDODS scenarios `Render API › Untrusted HTML is sanitized even when the caller asks otherwise` and `Rendered pages › Raw HTML in the source is sanitized in the page` check the same through the running server and in Chromium.

## Trusted slots

Code block handlers (syntax highlighting, diagrams, your own) return HTML that the sanitizer would damage: Shiki uses `style` for colours, diagrams are SVG. So their output skips the sanitizer and goes in through slots. That makes every handler part of the trusted computing base:

- `@markupme/highlight` escapes the code, the language and the title with `escapeHtml` before building its markup. Shiki produces the token spans.
- `@markupme/diagrams` passes every SVG (Blueprint, Graphviz, Kroki) through `sanitizeSvg`. The Mermaid provider escapes the source into `<pre class="mermaid">`. Error boxes escape the message and the source.
- Your own handler must escape its input the same way.

## SVG sanitizer

`sanitizeSvg` (`packages/diagrams/src/sanitize-svg.ts`) parses the SVG with `hast-util-from-html` in SVG space and removes:

- Elements: `script`, `foreignObject`, `iframe`, `object`, `embed`, `audio`, `video`, `image`, `animate`, `set`, `animateMotion`, `animateTransform`, `handler`, `listener`, plus comments and doctypes.
- Attributes: every `on*` handler; `href`, `xlink:href`, `src`, `action`, `formaction` unless they start with `#`, `http:`, `https:` or `mailto:`; `style` values containing `url(`, `expression` or `@import`.
- `<style>` contents with `@import` or `url(` pointing anywhere but `#`.

Graphviz `URL=` attributes and diagram labels are user input, and Kroki responses come from a server, which is why every SVG goes through this. The diagrams test `removes scripts, handlers, foreignObject and unsafe links` covers it.

## Mermaid

Mermaid needs a DOM, so it renders in the viewer's browser. The runtime initializes it with `securityLevel: 'strict'`. Mermaid is loaded only when the page has a Mermaid block, from (in order of preference):

1. A local copy: `render -s -o` copies `mermaid.min.js` into the assets folder; `serve` serves it at `/__markupme/mermaid.min.js`; `build` writes it into `assets/`.
2. Inline in the page: `--inline-assets`, or when writing a standalone page to stdout.
3. A URL you choose: `--mermaid-url <url>`. This is the only way a CDN gets involved.

See [ADR 0006](../architecture/architecture-decision-records/0006-mermaid-client-side.md).

## Kroki

PlantUML, C4-PlantUML, Structurizr, D2 and the other Kroki types render on a Kroki server. That sends the diagram source over the network, so the provider is used only when you pass `--diagram-server <url>` (or `diagrams.server` in the config). A self-hosted Kroki keeps source on your network. Requests time out after 15 seconds. Responses go through `sanitizeSvg`.

## Turning protections off

| Switch | Effect | Use when |
| ------ | ------ | -------- |
| `--no-sanitize` / `sanitize: false` | Raw HTML, `style`, scripts and handlers are kept. | The input is yours and you need raw HTML features. Never for user content. |
| `--no-html` / `allowHtml: false` | Raw HTML is dropped. Stricter, not weaker. | Comment boxes and similar. |
| `serve --unsafe` | API callers may send `sanitize: false`. | Local development on your own machine only. |
| `serve --host 0.0.0.0` | Binds every interface. | You understand the server is then reachable from your network. |
| `serve --cors <origin>` | Lets that origin call the API from a browser. | A local tool such as the studio needs it. |

Project rule: the sanitize default is never weakened in a pull request. Adding a tag, attribute or class to `markupmeSchema` needs a test in `describe('security')` that shows it cannot carry script.

## Lint rule

`MM015 unsafe-url` (error) reports `javascript:`, `vbscript:` and `data:text/html` URLs in links, images and definitions, so authors learn about them before the sanitizer silently drops them.
